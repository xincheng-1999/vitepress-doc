# 03 证书、私钥、签名和描述文件

## 1. 签名不是私钥

**私钥是用来产生签名的秘密材料；签名是计算结果。** 同一把私钥可以为多个版本签名，代码内容变化后，签名结果也会改变。

简化后的过程是：

```text
App 内容 → 计算摘要及签名数据 → 使用私钥签名 → 把签名附到产物
系统读取产物 → 计算并核对内容 → 用公钥验证签名 → 检查平台信任及授权规则
```

这是非对称密码学中的**数字签名与验签**，不是把 App 的全部代码加密。代码签名也不等于代码混淆或 DRM。

![证书、公钥、私钥、描述文件与签名产物之间的关系](/apple-development/signing.svg)

## 2. 每一种材料到底是什么

| 对象 | 包含什么 / 做什么 | 是否需要保密 |
| --- | --- | --- |
| 私钥 | 用来签名，不能从公钥或签名反推获得 | 是，核心敏感材料 |
| 公钥 | 用来验证对应私钥产生的签名 | 可以公开 |
| 证书 | 包含公钥、身份、用途、有效期、签发者签名等 | 公钥证书本身通常不属于秘密 |
| CSR | Certificate Signing Request，向苹果申请证书的请求，包含公钥等信息 | 不包含签名私钥 |
| 签名结果 | 对特定产物内容的签名 | 随产物分发 |
| 描述文件 | 苹果签署的 App、证书、能力、设备及有效期等授权集合 | 不含私钥，但可能包含团队和设备信息，避免随意公开 |

苹果证书证明一个公钥的身份和用途；描述文件进一步限定这个签名身份可以怎样签这个 App。系统验证的不只是“公钥能解开”，还包括证书链、能力匹配、分发方式等条件。

## 3. 证书如何产生

典型手动流程：

1. 在 Mac 上创建密钥对，私钥留在本机。
2. 生成 CSR，将公钥及申请信息提交给苹果。
3. 苹果签发证书，下载 `.cer` 并导入钥匙串。
4. 本机公钥证书和原先的私钥配对，成为可用的签名身份。

自动签名会替你管理这些步骤；某些分发流程还可使用云托管证书，不能简单理解为每种签名私钥都在当前 Mac 中。

**重新下载证书不会重新下载私钥。** 在电脑 A 上生成 CSR，在电脑 B 上只导入 `.cer`，B 通常仍然不能签名，因为配套私钥在 A 上。

## 4. `.cer`、`.p12`、`.mobileprovision`、`.p8` 的区别

| 文件 | 常见内容 | 用途 |
| --- | --- | --- |
| `.cer` | 公钥证书 | 导入、验证和建立证书链；单独不能代替私钥签名 |
| `.p12` / `.pfx` | 可封装证书和私钥，通常有导出密码 | 在授权设备间迁移本地签名身份；需确认确实包含私钥 |
| `.mobileprovision` | 描述文件 | 给特定 App、证书、设备和能力提供授权 |
| `.entitlements` | 工程请求的能力声明 | 参与构建和签名，不含私钥 |
| `.p8` | 特定服务的私钥文件 | 常见于 APNs、App Store Server API 等服务认证；用途要看密钥种类 |
| `.jks` / `.keystore` | Android 常见密钥库 | 通常保存 Android 私钥与证书，不直接用于 iOS 签名 |

不要把 App Store Server API 的 `.p8` 当作 Xcode 开发证书，也不要把 iOS 签名 `.p12` 交给前端代码调用支付接口。

## 5. 保存在哪，换电脑怎么办

**本地证书与私钥**通常在 macOS「钥匙串访问 → 登录 → 我的证书」中。展开对应证书时应能看到配套私钥；命令行可以检查有效签名身份：

```bash
security find-identity -v -p codesigning
```

输出有有效身份，只证明本机具备某些签名身份，不证明它们匹配目标 App 的团队和描述文件。部分证书名称里括号中的标识不是 Team ID，要查看证书 Subject 的 OU、团队页面或描述文件来核对。

**描述文件**在不同 Xcode 版本中常见于：

```text
~/Library/Developer/Xcode/UserData/Provisioning Profiles/
~/Library/MobileDevice/Provisioning Profiles/
```

自动管理时优先从 Xcode 界面查看，不必手动复制目录。开发签名产物中常可查看 `embedded.mobileprovision`，但不同分发渠道的最终产物形态可能不同。

换电脑通常有两种方法：让新电脑在团队权限下创建自己的开发签名身份，或由有授权的同事导出包含私钥的 `.p12`。不要为了给新同事开通开发，就撤销全团队正在使用的证书。

## 6. 看懂 Xcode 的证书管理窗口

![Xcode 证书管理窗口，标注开发证书、本机状态、其他设备证书和添加入口](/apple-development/xcode-certificates-annotated.png)

1. **Apple Development Certificates**：用于开发调试的证书列表，不是内购商品列表。
2. **Status**：查看当前机器是否具备可用的签名材料。
3. **Not in Keychain**：团队里有这张证书，但当前钥匙串没有对应的本地证书身份。仅从团队列表看到它，不代表当前机器就能用它签名。
4. **“+”入口**：可按权限创建新证书；教程只演示入口，没有实际创建或撤销证书。

设备名称和创建者已遮盖。已有一个合适的有效开发身份时，不要反复创建证书来碰运气。

## 7. 一套私钥和证书能用多久

- 不需要每次构建都重新生成。
- iOS 开发、分发证书通常有较短有效期，常见为一年；实际以证书类型和页面有效期为准。
- 证书到期后要按流程续签或重建签名身份，并更新相关描述文件，不能保证“下载一次终身可用”。
- iOS 的开发证书通常属于开发者或团队，可以签该团队下多个获授权 App，并非一个 App 永远独占一把私钥。
- 正常轮换 iOS 分发证书不会要求为原 App 改 Bundle ID，也不等于已经上架的 App 立即失效；开发包、Ad Hoc、企业分发和商店分发的有效期影响不同。
- Android 常规更新对签名身份连续性要求不同，不能把 Android 的原密钥保管经验机械套用到 iOS。

## 8. 三种常见签名用途

| 用途 | 常见证书 / 描述文件 | 谁能安装 |
| --- | --- | --- |
| 开发调试 | Apple Development + 开发描述文件 | 获授权测试设备，适合 Xcode 调试 |
| Ad Hoc 分发 | Apple Distribution + Ad Hoc 描述文件 | 描述文件包含的指定设备 |
| App Store Connect / TestFlight / 商店 | 分发签名及匹配上传配置；可能用云托管签名 | 上传并经平台处理后，按 TestFlight 或商店渠道安装 |

Debug / Release 是**构建模式**，不与上述签名用途一一对应。Release 优化代码也可以用于开发设备测试；它并不自动意味着正式 App Store 支付。

## 本章验收

如果同事说“证书给你了”，你会继续确认：是 `.cer` 还是包含私钥的 `.p12`？属于哪个团队？用途是否正确？是否过期？目标 App 和手机是否有匹配描述文件？
