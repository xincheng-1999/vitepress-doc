# 从家里登录公司服务器：VPN、堡垒机与跳板机

你在家办公，想登录公司的测试服务器查日志。同事说：“先连 VPN，再上堡垒机，申请测试机的访问权限。”

下面就按这个常见流程，看看每一步在做什么。

## 1. 先连 VPN，让电脑接入公司内网

公司的测试服务器通常不会直接对互联网开放。比如它使用 `10.20.3.8` 这样的私有地址，你在家知道这个地址，也未必有通往它的网络连接。

你按公司说明连接 VPN 后，电脑和公司之间就建立了一条加密通道。公司通过这条通道，让你访问工作需要的内部网络。这就是同事让你“先连 VPN”的原因。

现在解决的是网络怎么接进去。接下来，还要确认你有权登录哪台服务器。

## 2. 再上堡垒机，找到要访问的服务器

你打开公司的运维平台，用自己的账号登录，找到“任务系统测试机”。这个平台，就是很多公司所说的**堡垒机**。

堡垒机会根据你的权限，决定你能连接哪些机器。如果还没有测试机的访问权限，就先按流程申请。平台常把服务器等管理对象叫作“资产”，“申请资产权限”在这里就是申请访问这台服务器。

为什么还需要这个平台？因为公司不仅要让员工连上服务器，还要管理谁可以访问，并根据配置记录谁在什么时候做了什么。堡垒机把这些事情集中管理，就不必把服务器密码发给每个人。

### 连接时，跳板机又在做什么？ {#jump-vs-bastion}

假如你的电脑不能直接连接测试服务器，但能连接一台指定的中间机器，而那台机器又能连接测试服务器，就可以通过它中转。这台中间机器叫作**跳板机**。

所以，跳板机侧重“帮你连过去”；企业里的堡垒机平台通常还管理“你能进哪台机器”，并记录操作。中转功能可能由堡垒机本身提供，也可能由单独的跳板机承担，**不一定要再登录一套工具**。

![先通过 VPN 接入公司网络，再登录堡垒机申请并选择测试服务器，最后建立远程连接；中转可以由堡垒机或跳板机完成](/backend-guide/access-entry-map.svg)

## 3. 连接成功后，才是在服务器上操作

选好测试机并获得权限后，你就可以按公司的方式打开远程终端。有的在浏览器里打开，有的需要专用客户端。之后输入的命令，是在测试服务器上执行，不是在你自己的电脑上执行。

Linux 服务器常用 **SSH** 建立这样的远程连接，它会加密传输的数据。如果通过堡垒机访问，这一步可能由平台代你完成；你不一定需要自己输入 SSH 命令。

如果连接失败，先说清楚卡在哪一步。例如：“VPN 已连上，堡垒机也能登录，但点击测试机时提示没有权限。”这样同事就能从对应的位置检查，不必从头猜。分享错误信息时，记得隐藏密码、私钥等敏感内容。

到这里，我们先弄清了怎么进入服务器。进入后怎样找进程、看日志，会在后面的 [Linux 服务器起步](./21-linux-server-essentials) 中讲。

## 按需查阅

下面保留具体命令和其他接入术语。实际用到时，再展开对应部分。

### 用 SSH 经过跳板机 {#ssh-jump}

::: details 展开看：一条跳板连接命令是怎么工作的
SSH 是常用的远程登录方式。你在自己电脑的终端里连接服务器，登录以后，输入的命令就在远端执行，连接中的数据会被加密。

如果公司允许使用标准 SSH 中转，命令可能长这样：

```bash
ssh -J alice@jump.example deploy@app.internal.example
```

这里的账号和地址只是示意，不能直接连接。公司如果要求使用堡垒机客户端，就按公司的方式操作，不必套用这条命令。

从右边看，`deploy@app.internal.example` 表示用 `deploy` 这个账号登录目标应用机。前面的 `-J alice@jump.example` 则是在说：连接目标之前，先通过 `jump.example` 这台跳板机中转，跳板账号是 `alice`。OpenSSH 把这种方式叫作 `ProxyJump`。

本机客户端会经过跳板，与目标机器建立 SSH 连接。目标机器仍然会检查你的登录身份，数据也会在本机和目标之间保持 SSH 加密。

**第一次连接时的主机指纹提示，不要直接跳过。** 服务器会出示自己的主机公钥，指纹就是方便核对这把公钥的一段标识。先通过管理员或公司提供的可信记录核对，再接受；跳板和目标机器都要核对。以后如果出现密钥变化的警告，也应先问清是不是发生了重建或密钥轮换，而不是直接关闭验证。

接着才是你向服务器证明自己的身份。公司可能使用密码、个人密钥或短期证书。如果使用密钥，私钥留在你自己的受控设备上，公钥按流程授权给服务器账号。**使用 ProxyJump 通常不需要把私钥复制到跳板机。**

你还可能碰到 `ssh-agent`。它可以在本机代你用密钥完成签名，减少反复输入密钥口令的次数。Agent 转发会让远端也能请求这个签名能力，所以远端被攻陷时存在身份被冒用的风险；仅仅为了经过跳板连接，不要默认把它打开。
:::

### 数据库工具里，为什么有人让你填 localhost？ {#ssh-tunnel}

::: details 展开看：本地端口如何接到内网数据库
有时，公司会批准你通过一条 SSH 隧道访问测试数据库。这样，本机数据库工具连接一个本地端口，SSH 再把数据送到远端。

这必须是公司允许的连库方式。如果团队要求走数据库审计平台，就使用指定平台，不要自行建隧道来绕开它。

![本机数据库工具连接回环端口，SSH 经跳板到应用机，再由应用机连接内网 MySQL](/backend-guide/access-ssh-tunnel.svg)

先看这个示例中的路线：数据库工具连接你电脑上的 `127.0.0.1:13306`，数据经过跳板，到达应用机；**应用机**再去解析并连接 `mysql.internal.example:3306`。最后这一段连接不是由你的电脑或跳板机发起的。

对应的命令是：

```bash
ssh -J alice@jump.example -N \
  -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:13306:mysql.internal.example:3306 \
  deploy@app.internal.example
```

地址和账号同样只是示意。执行这类命令前，需要有对应的服务器、转发权限和数据库授权，不能仅凭教程中的命令接入公司环境。

`-J` 还是刚才的跳板设置。`-N` 表示只建立连接，不执行远程命令。`-L` 后面的前半段 `127.0.0.1:13306` 指定本机监听的位置，后半段 `mysql.internal.example:3306` 指定远端要连接的数据库。

这里特意使用 `127.0.0.1`，让端口只接受本机回环连接。不要为了给同事共用，把监听地址改成 `0.0.0.0`；那可能把你的连接通道开放给其他设备。

`ExitOnForwardFailure=yes` 则让初始监听或转发设置失败时退出。例如本机 13306 已被占用时，就不会让你误以为设置成功了。但数据库是否真的能连上，通常还要等客户端实际使用这条通道才能知道。

命令运行期间，保留这个终端。另开一个终端，或者在数据库工具中填入本机地址和 13306 端口，才是在使用这条隧道。下面展示的是 MySQL 命令行的写法，`-p` 会提示你输入密码，不要把密码直接写进命令：

```bash
mysql --protocol=TCP -h 127.0.0.1 -P 13306 -u reader -p
```

隧道只是帮你把连接送过去。MySQL 仍然会检查账号，以及它能访问哪些库表。

还有一段加密需要单独考虑：SSH 保护的是本机到应用机的连接，应用机到数据库这一跳要使用公司要求的数据库 TLS 配置。如果连接本机地址后，数据库证书的主机名校验不通过，应让管理员提供匹配的连接配置，而不是关闭证书校验。

用完后，在运行 SSH 的终端按 Ctrl+C 结束隧道。以上只是命令讲解，本教程没有实际连接公司 VPN、堡垒机或远程数据库；本机 CRUD 练习也不需要它们。
:::

### 其他接入术语

::: details 遇到这些词时，再展开看
**VPC、子网、路由表**经常一起出现在云平台上。公司把服务器放进一片自己配置的云网络，这片逻辑隔离的网络通常叫 VPC；里面可以划分子网，路由表则决定发往某个目标的数据该走哪条路。同一片网络里的机器，仍然可以通过访问规则彼此隔离。

**零信任接入（ZTNA）**是另一类接入方案。例如公司只允许你的受控电脑访问指定的内部应用，会根据你的账号、设备状态等条件判断是否放行，而不是给电脑开放整片内网。“零信任”说的是这种不因网络位置就直接信任的思路，不是装上某个客户端就绝对安全。它可能和 VPN、堡垒机配合，也可能代替其中某些接入方式。

VPN 还有**分流**和**全隧道**的区别。前者只让指定目标走 VPN，后者让更多或全部流量经过公司出口，实际以公司配置为准。VPN 隧道之外的连接，仍然需要 HTTPS 等协议提供相应保护。

**安全组和防火墙**按规则允许或拦截连接。例如，只允许指定来源访问数据库端口。**IP 白名单**则是列出允许的来源地址；它不代替数据库账号。经过 VPN 出口、跳板或代理后，目标看到的来源可能不是你电脑上的地址。办公网络还常通过 **NAT** 转换地址，让多台电脑共用一个出口，所以应按实际连接方式确认该放行谁。

**网络 ACL**也是一组允许或拒绝流量的规则。它和安全组的具体作用位置、规则顺序、是否跟踪已有连接，要看所用云平台的说明，不能把一家云的配置照抄到另一家。

**IAM**讨论的是账号、角色和权限怎样管理；**PAM**更关注管理员等高权限账号，例如密码如何保管和轮换、临时权限怎样收回。堡垒机可能承担其中一部分工作，但不会自动管理所有系统里的账号。能操作云控制台，也不代表已经获得服务器或数据库的登录权限。

这些词暂时记不牢也没关系。以后遇到具体工作，再回 [场景词典](./90-glossary) 查对应条目，带着问题看会更容易理解。
:::
