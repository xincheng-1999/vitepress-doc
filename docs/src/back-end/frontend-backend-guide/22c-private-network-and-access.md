# 公司内网怎么进：堡垒机、跳板机、VPN 与访问权限

> 场景：你想查 `task-api` 的测试环境日志，同事说「先连 VPN，上堡垒机，申请测试资产权限；连库还得开白名单」。这不是 Java 语法，而是**人怎样被允许进入运行环境**。

前置：[网络中的地址与路由](./22-networking-for-backend)、[代理与服务发现](./22b-proxy-and-discovery)。本章先建立地图，第一次不必真的申请服务器；具体 Linux 操作见 [服务器起步](./21-linux-server-essentials)。

**学习目标**：分清网络接入、连接中转、身份与资产授权、系统与数据库权限；听懂运维的接入要求；连不上时能按层提问，而不是直接开放所有端口。

::: warning 只有获授权的目标才能实操
本仓库不提供公司 VPN、堡垒机或远程资产，也不需要它们才能跑本机 CRUD。下面域名、账号、密钥路径均为占位；按公司正式接入方式替换，不能用隧道绕过审批、审计或数据库访问限制。初始教学 API 仍不能公开暴露。
:::

## 1. 先把「用户访问业务」与「开发者运维」分开

![业务用户通过 HTTPS 入口使用应用，运维人员通过受控接入和资产授权管理服务器，两种入口职责不同](/backend-guide/access-entry-map.svg)

- **业务入口**：用户打开任务网页，经过 HTTPS、反向代理、应用登录与数据归属检查。这是前面讲的 `/api/tasks`。
- **运维入口**：工程师为了查日志、发布或排障，通过指定网络与工具进入服务器 / 数据库。通常有独立的实名账号、MFA、审批、时限与审计。

能登录任务网页，不代表可以 SSH 服务器；能登录堡垒机，也不代表能修改任何任务或连接任何数据库。后端应用自己的数据库连接，则属于**服务身份与服务网络**，不是工程师每天手工登录堡垒机后才成立。

## 2. 公网、内网、VPC、子网：先知道地址属于哪里

| 说法 | 最小理解 | 常见误区 |
| --- | --- | --- |
| 公网 / 内网 | 公网面向互联网路由；内网地址在约定私有网络内使用 | 私有地址不等于安全或任何员工可达；公网地址也不等于端口已经开放 |
| 办公网 / 测试网 / 生产网 | 公司按使用者和环境划分的网络区域 | 连上办公室 Wi-Fi 不等于能访问生产资源 |
| VPC | 云上逻辑隔离的网络环境，可包含子网、路由和访问策略 | 同一家云或同一 VPC，不表示所有资源互相可达 |
| 子网 / 路由表 | 地址范围的划分 / 到目标前缀时选择下一跳的规则 | 子网被叫“公网子网”不代表其中每台主机都有公网地址和开放端口 |

例如 `10.20.3.8` 是私有 IPv4 地址。你在家里直接访问，可能既没有到公司网络的路由，也没有公司 DNS 的解析结果。改本机 hosts 只能改名字到地址的映射，**不能凭空创建路由、授权或监听进程**。

网络位置只是一层隔离。凭据泄露、错误配置或内部账号滥用仍会发生，所以内网也要有认证、加密、最小权限和审计。

## 3. VPN 与零信任：解决「怎样获准接入」

### VPN：给授权设备建立受控网络通路

VPN 常在设备与接入端之间建立加密隧道，再按配置向设备下发网络访问、路由、DNS 等能力。你可能只被允许到测试网，生产网仍被阻断。

- **分流隧道**：只让指定目标走 VPN；**全隧道**：更多或全部流量经公司出口。具体行为以管理员配置为准。
- 连接成功不保证 DNS、目标路由、安全策略、SSH 账号和数据库账号全部正常。
- VPN 只保护其隧道覆盖的区段；离开隧道后的链路仍按实际协议保护，业务 HTTPS / 数据库 TLS 不应因此被随意取消。

### 零信任接入 / ZTNA：按身份、设备与资源授予访问

常见方式是通过客户端、连接器或浏览器访问网关，结合人员身份、设备状态、资源、时间等策略，开放特定应用 / 协议，而不是默认把整个内网交给这台电脑。

「零信任」是设计思想，不是某个产品名，也不等于免密、绝对安全或不需要网络隔离。VPN、ZTNA 与堡垒机可以组合，**不是每家公司都必须把它们全装一遍**。

## 4. 跳板机与堡垒机：相关，但不完全等价 {#jump-vs-bastion}

| 项目 | 跳板机 / Jump Host | 企业语境的堡垒机 / 运维访问平台 |
| --- | --- | --- |
| 核心目的 | 从可达的一台主机中转到不能直达的资产 | 集中管理「谁在何时，以何账号，对哪项资产做了什么」 |
| 最小形态 | 一台允许受控 SSH 中转的主机 | 资产目录、账号与凭据管理、授权审批、访问代理和审计等组合 |
| 常见入口 | SSH `ProxyJump`，或按规范逐跳连接 | Web 终端、SSH 客户端、RDP、数据库客户端等，视产品和配置 |
| 它不天然保证什么 | 不天然包含实名审批、完整录像和凭据轮换 | 不天然获得目标系统权限，也不保证每条绕开平台的连接都被审计 |

英文 **bastion host** 在云文档中也常指经过加固的跳板主机；国内同事说“堡垒机”则经常指完整运维访问平台。先问清对方指哪一种，不要只凭中文 / 英文名判断功能。

一个典型过程是：你用个人账号和 MFA 登录平台 → 申请某个**测试资产**和某种操作角色 → 在批准时段建立会话 → 平台使用受控凭据或短期证书连接目标 → 按支持范围留存操作证据。你未必需要、也未必被允许拿到目标资产的长期密码。

**IAM 与 PAM 顺便区分**：IAM（身份与访问管理）管理人员 / 服务身份及权限；PAM（特权访问管理）更聚焦高权限账号、凭据生命周期、临时授权与会话控制。堡垒机常承担其中一部分，不等于替代所有 IAM / PAM 能力。

## 5. 安全组、防火墙、ACL、白名单：说清哪一层放行

同事说“开个白名单”时，先补全一句话：**允许谁的什么流量，从哪里，到哪个目标和端口，在什么时间内通过哪项策略？**

| 控制 | 常见位置与用途 | 仍不能替代什么 |
| --- | --- | --- |
| 安全组 | 云资源关联的网络流量策略，常按来源 / 目标、协议、端口配置 | 主机监听、系统权限、应用登录 |
| 防火墙 | 主机、网络边界或网关上过滤流量 | 账号认证、资源归属与 SQL 权限 |
| 网络 ACL | 按网络范围制定允许 / 拒绝规则 | 不同产品的顺序、状态与返回流量规则不能机械互抄 |
| IP 白名单 / allowlist | 只接受允许来源，可能在网络层，也可能在应用 / 数据库平台 | IP 不是人的身份，共享 NAT 出口可能对应很多人 |

各云的安全组 / 网络 ACL 在有状态、规则优先级、默认行为上可能不同；不要背成一套普遍规则。**来源地址也不一定是笔记本的 Wi-Fi 地址**：经过 VPN、NAT、堡垒机或代理后，目标可能看到公司出口、跳板或代理地址，应让管理员结合实际链路与日志确认。

提申请可以这样写，而不是“把 3306 全开放”：

```text
目的：排查测试任务列表，使用只读账号。
人员 / 设备：我的实名账号及公司受控设备。
来源：公司批准的接入入口 / 运维代理，来源由管理员核实。
目标：指定测试资产及其 MySQL TCP 3306，不包括生产库。
时限：本次排障窗口，过期自动收回。
约束：走平台审计，不导出真实个人数据，不开放 0.0.0.0/0。
```

## 6. SSH 怎么经过跳板：私钥不必放到跳板机上 {#ssh-jump}

SSH 提供加密连接，常用于远程终端、文件传输或受控转发；既要认证用户，也要验证**你连接的服务器是谁**。首次核对主机指纹，指纹变化先通过可信渠道查证，不能直接关闭主机密钥校验；经过跳板时，跳板与目标应用机的身份都要核对。

如果公司明确允许标准 OpenSSH 中转，下面是一条**命令阅读示例**：

```bash
# alice：跳板账号；deploy：目标应用机账号；两处授权各自检查
ssh -J alice@jump.example deploy@app.internal.example
```

本机 SSH 客户端经跳板打开到应用机的连接，再与应用机建立 SSH 会话；目标连接及凭据校验仍存在。通常不需要先把私钥复制到跳板机，也不需要为了 `ProxyJump` 默认开启 Agent 转发。

- 私钥保留在受控本机或公司要求的硬件 / 凭据系统；公钥或短期证书按流程配置。
- `ssh-agent` 可在本机提供签名服务；**Agent 转发**可能让有权访问转发 socket 的远端进程在连接存续期间借用签名能力，即使它不能直接读出私钥，也不是无风险。
- `~/.ssh/config` 可集中配置 `Host` 别名、`User`、`IdentityFile`、`ProxyJump` 等；已有文件先核对再改，不用一段教程覆盖全部个人配置。
- 有些堡垒机用特殊账号格式、Web 终端或专用客户端，或禁用 TCP 转发；这种情况下应使用公司正式入口，而不是强套 `ssh -J`。

## 7. 「连库要建隧道」是什么意思 {#ssh-tunnel}

**前提：公司明确批准这种转发，且相应资产与数据库都已授权。** 许多团队要求数据库审计平台、短期凭据或专用代理，而不是允许自行建隧道。

![本机回环 13306 经跳板到应用机的 SSH 会话，再由应用机连接内网 MySQL 3306，目标数据库账号与链路 TLS 仍独立检查](/backend-guide/access-ssh-tunnel.svg)

```bash
# 仅为获批场景的阅读示例：终端保持运行，Ctrl+C 结束隧道
ssh -J alice@jump.example -N \
  -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:13306:mysql.internal.example:3306 \
  deploy@app.internal.example
```

逐段解释：

1. `-J` 指定连接应用机时经过的跳板；它不自动授予应用机或数据库权限。
2. `-N` 表示不执行远程命令；不必为隧道打开一个交互 shell。
3. `-L` 只在**本机回环**监听 13306；本机客户端连接它，流量通过到应用机的 SSH 会话，**再由应用机**连接并解析 `mysql.internal.example:3306`。
4. `ExitOnForwardFailure=yes` 让初始监听 / 转发设置失败时退出，**不保证之后数据库目标一定可达**；目标连接通常在客户端真正使用时才发生。

例如另一个终端用 `mysql --protocol=TCP -h 127.0.0.1 -P 13306 -u reader -p` 发起连接，`-p` 后不写口令，按提示输入。具体数据库客户端及 TLS 参数由公司配置决定；需要校验证书时，**不能因为连接名变成 127.0.0.1 就随意关掉证书校验**，要用获批的主机名映射或连接方案。

隧道不负责 MySQL 用户与库表授权，也不把 SQL 变成 HTTP。SSH 加密覆盖到应用机这一段；应用机到数据库这一跳要按数据库 TLS 等方案保护。转发还受 SSH 服务端和网络策略约束。

**不要**把本机监听改成 `0.0.0.0` 给同事共用、把数据库密码写进命令行、复制私钥到跳板、随意开启 Agent 转发，或用隧道规避堡垒机审计。通道加密不等于操作已经获得业务授权。

## 8. 新人接入与排错：按边界收集证据

正式接入前先问：① 哪个环境和资产？② 用哪个个人身份、MFA 与受控设备？③ 从 VPN / ZTNA / 专线中的哪种入口进？④ 资产、系统、数据库角色是否各自获批？⑤ 操作能否审计，何时回收？

| 现象 | 先查哪一层 | 不能直接下的结论 |
| --- | --- | --- |
| 内网域名解析失败 | 名字是否正确、企业 DNS 和接入策略 | 不等于 Java 服务挂了；改 hosts 也不自动打通网络 |
| VPN 已连接，SSH 仍超时 | 实际路由、获批网络范围、目标监听与过滤策略 | 不等于账号密码错，不能先开放所有端口 |
| 能登录堡垒机，但看不到资产 | 资产授权、角色、审批时段 | 不等于目标服务器不存在 |
| SSH `Permission denied` | 目标账号、密钥 / 证书、认证方法及策略；有时也可能是在跳板认证阶段失败 | 不能靠反复 sudo、换端口或关闭指纹检查解决 |
| 主机指纹改变 | 与管理员核实重建、密钥轮换或异常连接 | 不直接删 known_hosts 记录继续连接 |
| 隧道进程还在，数据库不通 | 应用机到数据库的路由 / DNS / 端口，以及 DB TLS 与账号 | 本地 13306 在监听不是数据库健康证明 |
| 能查日志，不能读文件 / 执行 sudo | 系统用户、文件权限与授权范围 | 不等于堡垒机坏了，也不默认应该给 root |

求助时给脱敏的时间、观察位置、环境、目标资产标识、协议 / 端口、失败阶段和必要错误码。`ssh -v` 等诊断输出可能含内部地址、账号和密钥路径，分享前脱敏；不贴私钥、口令、Cookie 或完整会话录像。

## 9. 不连公司服务器，也能完成的练习

听到“先连 VPN，上堡垒机查生产日志，连库还要开白名单”时，把它拆成一张访问申请图：

- 谁、哪台设备、从哪一网络入口进？哪些是测试，哪些是生产？
- 哪台资产，用哪种协议和系统角色？为什么只读足够？
- 目标实际看到的来源是谁？批准多长时间，退出 / 到期怎么收回？
- 需要什么审计证据，哪些信息不能复制到本机？

**预期结果**：能说清至少“网络可达、平台资产授权、系统认证、数据库 / 业务授权”四层，而不是“给我个 IP 和 root 密码”。这些是纸面与命令阅读练习，**本教程未实际连接任何公司 VPN、堡垒机或远程数据库**。

## 自测与参考答案

1. 跳板机一定是带录像和审批的平台吗？**不是。它最小只提供受控中转；企业堡垒机平台常增加治理能力，名称仍要按上下文确认。**
2. VPN 连上、堡垒机登录成功，为何数据库仍拒绝？**接入、资产授权、网络路径、SSH / 数据库身份和库表权限是不同边界，成功一层不代表全部成功。**
3. 隧道需要把本机私钥传到跳板机吗？**标准 ProxyJump 通常不需要；按公司受控凭据方案认证，不默认复制私钥或开启 Agent 转发。**
4. 业务应用平常连数据库，也都要经过工程师的堡垒机会话吗？**不是。业务连接通常使用服务身份和受控网络；人的运维入口是另一条路径。**
