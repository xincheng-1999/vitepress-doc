# 怎样安排学习，卡住时怎么办？

阅读顺序按 [学习地图](./index) 即可。本页不再排另一套周计划，只说怎样把一篇内容真正弄明白。

## 每次完成一个小步骤

不必一口气读完一篇。比如学习 CRUD，可以先做到“应用启动，创建一条任务”，下一次再查询和修改。

读完相关说明，就实际发一次请求，看结果是否和解释相符。然后改变一个条件：把标题改为空，或查询不存在的 ID，观察结果为什么变了。正常请求和错误请求放在一起看，比只记状态码更容易理解。

如果每天只有半小时，就把同一个实验分几天完成。学得慢并不需要额外补一堆术语；先找出当前究竟是哪一步没弄懂。

## 卡住时，回到对应的位置

| 现在卡在哪里 | 先做什么 |
| --- | --- |
| Java 或 Maven 命令启动不了 | 回 [环境检查](./05-java-crash-course)，确认命令使用的 JDK，不要同时换框架和依赖版本 |
| 拿到地址，却连不到应用 | 对照 [网络](./22-networking-for-backend) 分清域名、地址、端口；进入应用后再看 [日志](./26-reading-logs) |
| VPN 连上，还是进不了测试机 | 对照 [堡垒机接入过程](./22c-private-network-and-access)，说清卡在平台登录、目标权限还是远程连接 |
| 找不到对象是在哪里创建的 | 回 [Spring 的对象管理](./06-spring-boot-ioc-di)，沿构造器看需要哪些依赖 |
| 不知道表和 SQL 怎么写 | 回 [任务数据建模](./10-sql-and-indexes)，先完成一条保存和一条查询 |
| 登录成功，却能访问别人的任务 | 对照 [权限检查](./32-security)，看查询和修改是否限制了当前用户 |
| 重试后出现重复任务 | 回 [事务](./11-transactions-consistency) 和 [后台任务](./33-mq-reliability)，区分“有没有提交”和“重复执行会怎样” |

## 留下少量能帮助下次继续的记录

不用为每一课交一份长报告。记下你使用的版本、执行的关键命令、实际结果，以及卡住后怎样解决就够了。涉及账号和内部地址时，先脱敏。

画图也只画当前需要理解的过程。比如新增任务，就从页面到后端、再到数据库；还没用到的缓存和消息队列，不必提前塞进去。

如果参考 AI 给出的命令或解释，仍要自己确认结果。教程里的示意输出和你机器上的实际输出是两回事。

## 先完成主线，再按问题深入

第一轮先把一个小任务功能做完整：能保存和查询，能区分用户，知道启动配置在哪里，出错时能找到对应日志。

Spring 源码、GC 参数、Kubernetes 集群和微服务治理，可以留到确实需要时再学。选修不是写第一个接口之前的门槛。

两份示例也要分开看：初版有 7 个 CRUD 测试，登录实验有 16 个会话与隔离测试。H2 测试通过之后，切换 MySQL、容器或生产环境，仍要检查新环境里的行为，不能直接照搬结论。

读到主线最后的 [综合实战](./38-capstone-feature-to-prod) 时，再把这些内容组合起来。想继续从当前位置学习，就回到 [学习地图](./index)。
