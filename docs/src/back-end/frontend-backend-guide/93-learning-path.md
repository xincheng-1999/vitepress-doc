# 学习节奏与检查点

> 顺序只有一份：以 [课程学习地图](./index) 为准。本页只回答怎么安排时间、卡住怎么补、怎样证明真的学会，避免再维护一套矛盾路线。

## 1. 学习单位不是一篇文章，而是一个闭环

每次安排 60～120 分钟，可拆成：读一个小节 → 画图 / 解释 → 跑一次正常路径 → 故意制造一个失败 → 保存证据和结论。

**时间只是参考，不是承诺。** 如果你每天只有半小时，把同一个闭环拆成两三天；不要为了「第几周学完」跳过不理解的基础。

| 建议节奏 | 对应主线 | 检查点 |
| --- | --- | --- |
| 第 1 周 | A：责任、系统与网络 | 画出一次请求，解释 DNS / 端口 / TLS / 代理 |
| 第 2 周 | B：最小 Java、Spring、CRUD | 运行示例和 7 个测试，自己加一个合法字段 |
| 第 3 周 | C：SQL 与事务 | 设计 users/tasks，复现回滚和旧版本冲突 |
| 第 4 周 | C：认证、授权和测试 | A 不能读写 B 的任务，未登录与过期都有测试 |
| 第 5 周 | D：真实功能地图 | 选附件或导出，写清最小实现与失败边界 |
| 第 6 周 | D：缓存 / 异步 / 连接池 | 会解释用途；只有需求需要时才集成组件 |
| 第 7 周 | E：环境、Linux、Docker | 在本机 Compose 跑 MySQL，重建后数据仍在 |
| 第 8 周及以后 | E：日志与综合验收 | 完成交付、故障记录和隔离备份恢复 |

## 2. 如果只想先听懂同事

先读 [系统地图](./02-architecture-overview)、[请求链路](./03-request-lifecycle)、[网络三篇起点](./22-networking-for-backend)、[功能地图](./39-backend-feature-map)，遇词查 [150 条场景词典](./90-glossary)。

到会议里不要只问「这个词是什么意思」，还问：

- 它解决哪一个需求？放在哪一跳？
- 如果不用它，会出现什么问题？
- 它失败时，用户看到什么？数据是否可能已提交？
- 它是当前系统正在用，还是将来才需要的方案？

这是快速认知路线，不等于已经具备独立后端交付能力。理解之后仍要补主线动手。

## 3. 卡住时先补哪一块

| 卡点 | 回到哪里 | 不建议 |
| --- | --- | --- |
| 命令启动就失败 | [JDK / Maven](./05-java-crash-course)、错误最末端原因 | 同时改 Java、框架和所有依赖版本 |
| 不知道请求到没到应用 | [网络](./22-networking-for-backend)、[日志](./26-reading-logs) | 先把所有超时调成无限大 |
| 看不懂类之间为什么自动连接 | [Bean 与构造器注入](./06-spring-boot-ioc-di) | 背完全部 Spring 注解再回来 |
| SQL 不知道怎么写 | [数据模型与 SQL](./10-sql-and-indexes) | 只让 AI 生成 Entity，忽略表和约束 |
| 登录后仍可访问别人数据 | [动作与归属授权](./32-security) | 只在前端藏按钮 |
| 重试后重复执行 | [事务与幂等](./11-transactions-consistency)、[消息可靠性](./33-mq-reliability) | 认为有锁 / MQ 就自动只执行一次 |

## 4. 每阶段只留三件学习记录

1. **一张图**：自己重画，不是复制教程 SVG。能标出进程、网络、持久数据、信任边界。
2. **一个实验**：命令、脱敏输入、实际输出、环境版本和预期对比。不要把教程「预期输出」当实测记录。
3. **一份失败分析**：错误出在哪一层，哪些证据支持，修复怎么验证。

可以让 AI 帮你解释和补测试，但不要让它替你声称已经跑过未执行的步骤。尤其 H2 与 MySQL、MockMvc 与浏览器、容器运行与生产上线，都不是等价证明。

## 5. 第一轮明确可以不学什么

Spring 源码、GC 调参、Kubernetes 集群管理、分布式事务框架、微服务全家桶、大规模搜索集群。它们是之后的专题，不是写出一个安全小系统之前的考试。

选修旧文可能用 `svc-*` / `RtData` 生图场景，作为架构片段理解即可，不要找一个本仓库不存在的完整微服务项目。第一轮的可运行起点始终是 [task-api](./07-build-a-crud-api)。

## 自测

- 能说清请求在代理、应用和数据库之间如何走吗？
- 能不用看教程解释身份与数据归属吗？
- 能证明重启后不丢、失败会回滚、旧版本更新冲突吗？
- 能在别人电脑重现运行，并恢复一次测试备份吗？

答不上来不是要读更多术语，而是回到对应阶段完成一个小闭环。最终按 [综合实战检查表](./38-capstone-feature-to-prod) 验收。
