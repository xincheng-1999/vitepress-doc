# 前端工程师的 Flutter 实战：与 AI 一起交付 App

你已经会 JavaScript，可能还会 React、Vue 或 TypeScript。现在有大模型帮忙写代码，学习 Flutter 的重点也变了：你不必先背完组件库，但必须知道**该让模型写什么、哪些设计不能交给它猜、怎样证明结果是对的**。

这套教程围绕一款「随手记」App 展开：列表、新增与编辑、删除、本地数据库，然后按需增加远程搜索、图片、权限和发布。Dart 只讲与 JS 不同且会影响读代码、写需求和排错的部分；Flutter 则深入到状态、生命周期、布局、异步和平台机制。

## 学完要能交付什么

主线交付物是一款离线笔记 App：

- Android / iOS 页面可用，键盘、返回键、长文本、大字体有明确行为。
- 列表、新建、编辑、删除形成闭环，重启后数据仍在。
- 保存失败不会提示成功，也不会丢掉用户正在输入的草稿。
- 能用测试验证核心行为，能在真机上安装 release 包。

网络、图片是第二阶段能力；账号与多端同步是进一步扩展，本文会解释边界，不假装一个 HTTP 请求就实现了同步。完成 Android 主线不要求你先买 Mac；iOS 本机构建需要 macOS 与 Xcode。

## 怎么读：按能力验收，不按天打卡

| 阶段 | 读什么 | 可以进入下一阶段的证据 |
| --- | --- | --- |
| 跑通工具链 | 01 | 能在目标设备启动和热重载 |
| 看懂真实项目 | 项目导读、02 | 找出实际启动命令、入口、路由和模块，追踪一次保存 |
| 能判断 UI 是否正确 | 03、04 | 能解释溢出原因，支持小屏、大字体、键盘与暗色模式 |
| 做出完整功能 | 05、06、08、09 | 新建到持久化再返回列表，状态和错误都有去向 |
| 获得可运行基线 | 17，并对照 12 | 整合示例通过 analyze 与测试，真机重启数据不丢 |
| 接入外部能力 | 07、10、11 | 弱网、取消、权限拒绝、图片临时文件均有处理 |
| 交付到设备与用户 | 13—16 | 用签名产物完成安装、覆盖升级和回归 |

每章的代码都标明用途：**完整文件**可以按指定路径保存；**局部示例**用于解释一个机制，不能依次拼成应用。第 17 章提供统一基线，解决“每章都能看懂，合起来却跑不动”的问题。扩展功能以这份基线为起点逐项接入。

## 与 AI 的分工

你负责业务约束、状态模型和验收；模型负责检索 API、生成重复代码、补测试和提出修改。交给模型之前先用一句话说清业务不变量，例如：“保存失败必须保留草稿，只有数据库写入成功才能返回列表”。这比“帮我写个编辑页”有用得多。

每轮只完成一条纵向功能：触发操作 → 状态变化 → 数据访问 → UI 反馈 → 失败恢复。让模型给出小范围 diff，运行后再继续。不要同时升级依赖、重写路由、换状态库和补页面，否则你无法判断哪一步引入问题。

可直接使用的任务描述：

```text
项目：Flutter 随手记；先读取 pubspec.yaml、pubspec.lock 和相关文件。
本轮目标：编辑笔记并持久化，只修改这条功能链涉及的代码。
现有约束：UI -> Riverpod Notifier -> NotesRepository -> SQLite。
业务规则：内容 trim 后非空；提交期间禁用重复操作；失败保留草稿；
数据库成功后才返回列表；不可在 build 中写库、重设 controller 或创建 router。
请先复述状态变化和需要修改的文件，再实现。
给出正常、失败、连续点击三个场景的测试；执行 format/analyze/test。
说明没有验证的设备行为；不要声称测试通过，除非提供实际结果。
```

如果你无法解释模型修改的状态归属、异步边界或数据库字段，先让它画出数据流并举一个失败场景，再接受代码。不要用“请检查有没有问题”代替具体验收。

## 版本与复现

本文整合示例使用 Flutter **3.38.7 / Dart 3.10.7** 作为验证基线，不代表它们是最新版。使用 Dart 3 的 records、patterns、sealed class，以及 Riverpod 3 的非代码生成 API。示例依赖固定在第 17 章，便于复现。

新项目可以使用当前 stable，但要读插件的 SDK 要求与迁移说明。`flutter pub add` 解析到的版本可能随时间变化，不能把旧博客片段与最新 API 混用。应用项目应保存 `pubspec.lock`，记录 Flutter 版本；升级独立成一次可验证的改动。
